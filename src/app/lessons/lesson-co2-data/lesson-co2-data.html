Data pipeline II: CO₂

The second dataset: Our World in Data's CO₂ and Greenhouse Gas Emissions, country by country, year by year. Like the boundaries in lesson 02, a Node script turns it into small files once, and the app only reads those. The first place it shows: select a country, and the card lists its latest CO₂ per person, per year, and its share of all CO₂ since 1750.

npm run data:co2            # uses the cached download
npm run data:co2 -- --fresh # downloads again

1. The source

  • owid-co2-data.csv: 14 MB, 50 000 rows (one per country or region per year, 1750–2024), 71 columns. The numbers come from the Global Carbon Budget; OWID cleans and joins them.
  • owid-co2-codebook.csv: a title, definition, unit and source for every column. The script copies these into meta.json, so the app quotes OWID's own definitions instead of paraphrasing them.
  • Pinned to a commit (382ee6c, 2 June 2026) instead of master: the same input always gives the same output, and an update is a deliberate one-line change.
  • License: CC BY 4.0, which requires attribution. Natural Earth was public domain; this one must be credited on the page (lesson 19).

2. From 71 columns to 7 small files

MetricWhy
co2_per_capitaResponsibility per person: the main colouring in lesson 09
co2Total per year: size of the problem, extrusion height in lesson 15
cumulative_co2, share_global_cumulative_co2Historical responsibility: who caused the CO₂ already in the air
consumption_co2_per_capitaEmissions of what a country consumes, including imports. Only 120 countries.
population, gdp_per_capitaContext, and the scatter plot in lesson 13. GDP per capita is derived: GDP ÷ population.
 
public/data/co2/co2_per_capita.json
{ "metric": "co2_per_capita", "firstYear": 1900,
  "values": { "FRA": [3.23, 3.12, …, 4.068, 3.969], … } }   // 125 values: 1900 → 2024
  • One file per metric, loaded only when it's shown: the card loads 3 of the 7. Each is 12–70 kB gzipped; all 7 together would be ~280 kB.
  • Columnar: one array per country, indexed by year − firstYear. A year's value is one lookup, and there are no repeated keys like {"year":1950,"co2":…} 27 000 times.
  • From 1900: earlier years exist, but for only a handful of countries.
  • 4 significant digits (4.068 t, 270.3 Mt): more would be false precision and bigger files.
  • Joined on ISO alpha-3, the same ids as lesson 02's boundaries. Rows without an ISO code are regions and aggregates (World, "High-income countries") and are skipped. So are two places we don't draw (Christmas Island, Bonaire).
  • Keys are sorted, so the output is byte-identical run to run.

3. Missing data is normal

  • null, never 0: a missing value and "no emissions" are different statements. On the map in lesson 09, null becomes its own "no data" style, not the lightest colour.
  • Each figure carries its year. CO₂ runs to 2024, consumption-based CO₂ to 2023, GDP to 2022. latest(series, id) returns the last value at or before a year, together with that year, and the card prints it.
  • 24 countries on the globe have no data at all: small dependencies (Guam, Puerto Rico, the Cayman Islands…), plus Kosovo, Somaliland, N. Cyprus, Siachen and Western Sahara. The card says "No CO₂ data… in Our World in Data" instead of showing zeros.

4. Validating at the boundary

httpResource(() => `data/co2/${id}.json`, { parse: parseSeries })
  • TypeScript types vanish at runtime: httpResource<MetricSeries> would accept any JSON and call it a MetricSeries.
  • The parse option runs on the raw response first. parseSeries checks the shape and throws if it's wrong, and the throw becomes the resource's error(). A broken or outdated file fails at the door, with a message, not three components later as "Cannot read properties of undefined". ≈ zod's schema.parse() in a fetcher, without the dependency.
  • Co2Data.metric(id) creates each resource once and shares it: the card and lesson 09's map both use co2_per_capita, with one request. Outside a constructor, httpResource needs { injector }.

5. Western Sahara, revisited

  • Lesson 02 kept Natural Earth's de facto borders: the coastal strip west of the Berm is drawn as part of Morocco, the interior as Western Sahara (ESH).
  • OWID has no rows for Western Sahara at all, in any year (nor for Kosovo). So the interior shows "no data" whichever border we draw.
  • With the ISO borders instead, the coastal strip would be "no data" too, rather than Morocco's colour. Morocco's own figures are the same either way: they come from the Global Carbon Budget's national totals, not from our shapes.
  • Verdict: the difference is a few hundred kilometres of coastline changing between Morocco's colour and "no data". Not worth switching to the 1:10m ISO file. Kept de facto, and noted for the methodology page (lesson 19).

Review checklist

  • npm run data:co2: the report lists 1900–2024, 216 of 240 countries, the no-data list, file sizes
  • Run it twice: git status shows no changes in public/data/co2/
  • Select France, Qatar, DR Congo: per person ranges from 41 t (Qatar) through 4 t (France) to 0.05 t (DR Congo) in 2024
  • Select Western Sahara or Kosovo: "No CO₂ data", not zeros
  • In the inspector, switch to GDP per capita: its latest year is 2022, not 2024
