Data pipeline I: boundaries

Before anything is drawn, the app needs two things: where each country is (geometry) and what it is (an id, a name, a region). This lesson adds a Node script that builds both once, at build time, and writes them to public/data/. The app only ever reads those two files.

npm run data:boundaries            # uses the cached download
npm run data:boundaries -- --fresh # downloads again

1. Why a build script, not a live API

≈ Next.js getStaticProps, or a Razor app reading a seeded table instead of calling an API on every request. The raw download goes to scripts/.cache/, which git ignores; the outputs in public/data/ are committed.

2. The source: Natural Earth

  • Natural Earth admin-0 countries at 1:50 million scale: 242 shapes, public domain, so no attribution is required (we'll still credit it in lesson 19).
  • 1:50m, not 1:110m: the smaller file drops microstates like Monaco and the Vatican. A globe you can zoom into needs them.
  • Boundaries are political choices. Natural Earth draws de facto borders; Kosovo, Somaliland and N. Cyprus are separate shapes. The script keeps the shapes and records what is unusual about them (section 3).

3. One stable id per country

Every dataset in later lessons (OWID CO₂, World Bank, ND-GAIN) identifies countries by ISO 3166-1 alpha-3: FRA, NOR, BRA. The geometry has to use the same codes, or nothing joins. Natural Earth has three code fields, and the obvious one is wrong:

FieldFranceKosovoProblem
ISO_A3-99-99Strict ISO: France and Norway get -99 because their overseas parts are separate shapes
ISO_A3_EHFRA-99"ISO, except here": fixes France and Norway. Used.
ADM0_A3FRAKOSNatural Earth's own code. Fallback for the 4 areas without ISO
  • Kosovo → XKX, the World Bank's code. OWID uses OWID_KOS; lesson 08 maps that.
  • Somaliland (SOL), N. Cyprus (CYN), Siachen Glacier (KAS) keep Natural Earth's codes. Statistics count them inside Somalia, Cyprus and India/Pakistan, so they'll show as "no data". That's honest: we don't have separate numbers for them.
  • Australia appears 3 times (the mainland, Indian Ocean Territories, Ashmore and Cartier Islands), all coded AUS. They're merged into one shape, so hover and colour treat them as one country.
  • Dependencies get a sovereign field: Greenland is GRL with sovereign: 'DNK'. Some datasets report Greenland on its own, some inside Denmark.
  • Western Sahara is split along the Moroccan Berm, the sand wall that separates the Morocco-controlled west from the Polisario-controlled east. The coastal strip belongs to MAR, the interior to ESH (Natural Earth's note: "Self admin.; Claimed by Morocco"). That's why the globe shows a border running parallel to the coast.

Decision: de facto borders, for now

  • Kept as Natural Earth draws them. Most statistics (OWID, World Bank, UN) follow the ISO/UN map instead, where Western Sahara is one territory and Morocco ends at the 27°40′N line.
  • Consequence once countries are coloured by data (lesson 09): Morocco's colour also covers the coastal strip, and Western Sahara's own value covers only the interior.
  • The alternative is Natural Earth's ISO point-of-view file, which draws Western Sahara whole. It only exists at the 1:10m scale (there's no 1:50m version), so the script would download a much larger file and simplify harder.
  • To revisit in lesson 08, when the CO₂ data shows how much it matters. Either way, the choice goes on the methodology page in lesson 19.

4. GeoJSON → TopoJSON

topology()      GeoJSON → TopoJSON: each shared border stored once, as an "arc"
mergeArcs()     the 3 AUS shapes → one MultiPolygon
presimplify()   weight every point by the spherical area it adds
protect         short arcs (microstates, small islands) get weight ∞
simplify()      keep the 25% heaviest points
quantize(1e5)   snap to a grid, store points as small integer deltas
  • Topology: in GeoJSON, the France–Spain border is stored twice, once in each country. In TopoJSON both reference the same arc. It's smaller, and simplifying an arc moves both sides together, so there are no gaps or overlaps between neighbours.
  • Spherical simplification: we draw a globe, so sphericalTriangleArea decides which points matter. A flat measure would over-simplify near the equator and keep too much near the poles.
  • The microstate bug: the first run simplified Vatican City down to a single point. Its whole outline is one short arc, and every point on it had a tiny weight. Arcs of 24 points or fewer are now protected: +24 kB, and every country keeps at least 5 points.
  • Quantize last: the first run quantized up front and came out at 2.4 MB, because presimplify had added a weight to every point. Quantizing at the end drops the weights, and the file went to 594 kB (191 kB gzipped).

  • Run it twice: git status shows no changes to public/data/ (same input, same output)
  • In the inspector above, look up FRA (not -99), Kosovo (XKX), Greenland (sovereign DNK), Vatican
  • Read the "ISO_A3 vs ISO_A3_EH" comment in the script and decide whether you agree with the 4 no-ISO choices
