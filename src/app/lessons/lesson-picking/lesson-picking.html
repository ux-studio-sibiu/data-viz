Picking

On the globe, hover a country to light it up and see its name; click to select it. A card in the top-left shows what's selected. The flat map does the same, and both share one selection: select France on the map, switch to the globe, France is still selected.

1. From the pointer to a country

pointer (px)  → -1…1 on both axes ("normalized device coordinates")
              → a ray from the camera through that point   raycaster.setFromCamera
              → where it hits the sphere                   ray.intersectSphere
              → lon / lat                                  vector3ToLonLat
              → a pixel of the ID map                      idAt
              → a country number → features[n - 1].id
  • A maths sphere, not the mesh: the globe is a perfect sphere of radius 1 at the origin, so the ray is tested against new Sphere(origin, 1). Three.js's usual raycaster.intersectObject(mesh) would test 49 000 triangles; this is a few multiplications, and exact.
  • The ID map does the rest: lesson 05's texture already knows which country covers every pixel. Picking reads the same pixel the shader draws, from the CPU copy of the array (idAt). Reading pixels back from the GPU (readPixels) would stall the pipeline.
  • Because both use the same map, what you see lit up is exactly what the click selects, down to the 10 km pixel.
  • vector3ToLonLat in geo.ts is the inverse of lesson 04's lonLatToVector3, and the same formula as the shader's.

2. Highlighting: two uniforms

uniform float hovered;   // country number, 0 = none
uniform float selected;
if (abs(id - hovered) < 0.5) base = hoverColor;  // floats: compare with a tolerance, never ==
if (abs(id - selected) < 0.5) base = selectColor;
  • Changing the hovered country updates one number on the GPU and draws one frame. Nothing is rebuilt.
  • An effect maps the ids ('FRA') to ID map numbers through a computed lookup. So it doesn't matter who changed hovered: the globe's pointer, the flat map, or the country list in lesson 07.
  • Selected wins over hovered, on both views. On the map, that's why the selected path is drawn last.

  • The same rule as learn-angular's GSAP lessons: per-frame values bypass Angular, discrete state goes through signals. hovered.set() is only called when the id actually changes.
  • The tooltip's content comes from the explorer through a slot ([globe-tooltip]), like the flat map's. Its visibility is a separate pointerOnCountry signal: a country hovered on the map shouldn't pop up a tooltip on the globe at a stale position.

4. Click vs. drag

  • Dragging rotates the globe, so every drag also ends with a pointerup. A press counts as a click only if the pointer moved less than 5 px between down and up.
  • Clicking the ocean (or the map's sea) clears the selection. So does the ✕ on the card.
  • Touch has no hover: hover logic is skipped for pointerType === 'touch' and while a button is pressed. A tap still selects.

5. One selection, two views

  • hovered and selected are model()s on both Globe and FlatMap. The explorer owns the two signals and binds both views with [(hovered)] and [(selected)].
  • The views don't know about each other. The explorer is the single source of truth, ≈ lifting state up in React.
  • The card uses aria-live="polite", so screen readers announce a new selection. Real keyboard access to countries comes with the search list in lesson 07.

Review checklist

  • Hover around the globe: the lit country, the tooltip and the cursor (pointer over land, grab over sea) all agree
  • Click France: Corsica and French Guiana light up too. Drag the globe: the selection stays
  • Switch to Map: France is still selected. Click Brazil, switch back: Brazil on the globe
  • Click the ocean: the selection clears
  • Zoom far into a coast and hover right at the border: the tooltip changes exactly where the colour does
