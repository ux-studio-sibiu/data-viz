Stores and the URL

The explorer's state now lives in one store, and the parts worth sharing live in the URL. Select a country and the address bar says ?country=FRA; switch to the map and it adds &view=map. Copy the link, reload, press back: the same screen every time. And there's a search box: press / and type.

  • Try: Norway on the map, the Vatican on the globe.

1. The URL as the source of truth

// pages/explorer/explorer-state.ts
private readonly params = toSignal(router.events.pipe(
  filter(e => e instanceof NavigationEnd),
  map(() => router.routerState.snapshot.root.queryParamMap)));

readonly selected = computed(() => { …params().get('country')… });
select(id) { router.navigate([], { queryParams: { country: id } }); }
  • Reading is a computed over the query params. Writing is a navigation. There's no second copy of "the selected country" to keep in sync with the URL, so the two can't disagree.
  • toSignal() turns the router's event stream (RxJS) into a signal. It's the bridge between Angular's older Observable APIs and signals.
  • navigate([]): empty commands mean "stay on this page" (and keep the lesson window's outlet); only the query params change.
  • The URL is validated, not trusted: ?country=fra works (upper-cased), and an unknown code is ignored instead of breaking the page. The check waits for countries.json, because computed re-runs when it arrives.
  • ≈ Next.js useSearchParams() + router.push({ query }), or the nuqs library.

2. What goes in the URL, and how

StateWhereWhy
Selected country?country=, new history entryWorth sharing; back undoes a selection
Globe or map?view=map, replaces the entryWorth sharing, not worth stepping back through. The default (globe) leaves the URL clean.
Hovered countrya plain signalChanges many times a second, never worth sharing
No WebGLa plain signalA fact about this browser, not part of a link
  • Year and metric (lessons 09–12) will go in the URL the same way.
  • The globe and the map bind [(hovered)]="state.hovered" straight to the store's signal: two-way binding works with any WritableSignal. Selection uses [selected] + (selectedChange)="state.select($event)", because writing it means navigating.

3. Keeping the query when navigating elsewhere

  • Router navigations drop the query params by default. Opening a lesson in the window (/(lesson:lessons)) would have cleared the selection.
  • Fixed once, for the whole app: withRouterConfig({ defaultQueryParamsHandling: 'merge' }) in app.config.ts. Every routerLink and navigate() now keeps the current params unless it sets them. Going to a full-page lesson and back to Explore keeps the selection too.

4. One store for the explorer

  • ExplorerState replaces lesson 05's ExplorerView service and the explorer's own hover/selection signals. The header's switch, the explorer, the globe, the map and the search all read and write the same instance (providedIn: 'root').
  • It's a plain class with signals, computeds and methods: no NgRx, no actions, no reducers. ≈ a Zustand store, or a React context with a custom hook. The signal-store pattern from learn-angular lesson 05, now with the router as a dependency.

5. The search: an accessible combobox

  • The keyboard way into the globe, and the only practical way to reach microstates: the Vatican is smaller than one pixel at the default zoom.
  • ARIA combobox pattern: focus stays in the input (role="combobox"). ↑/↓ move a highlighted option, and aria-activedescendant tells screen readers which one. Enter selects; Esc closes. The list is a role="listbox" of role="option"s.
  • The highlighted option is written to state.hovered, so it lights up on the globe or map before you choose.
  • Results rank an exact code first (FRA), then names starting with the text, then names containing it, up to 8.
  • Two details that are easy to miss: (mousedown)="$event.preventDefault()" on the list keeps the input focused, otherwise its blur would close the list before the click lands. And the document-level / shortcut ignores keys typed into fields.
