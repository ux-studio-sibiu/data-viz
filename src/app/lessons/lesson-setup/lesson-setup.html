Lesson 00

Setup & app shell

A fresh Angular app with only what the next lessons need: a product page, a lazy lessons area, and a dark stage for the globe. Three.js, GSAP and D3 aren't installed yet. Each library arrives in the lesson that first uses it, so every dependency shows up in a diff next to its reason.

1. The command

npx @angular/cli@21 new data-viz --directory . --style=scss --routing --ssr=false --zoneless --skip-git --skip-tests --ai-config=none
FlagWhy
@21Angular 22 needs Node 22.22+. This machine has Node 20, so the project starts on 21, the previous major (still supported). After upgrading Node it's one ng update.
--ssr=falseA WebGL globe can't render on the server, and there is no content worth indexing before the data loads. No SSR means no isPlatformBrowser checks around Three.js and GSAP.
--zonelessThe default since 21, passed explicitly so it's visible. See section 2.
--skip-gitng new would otherwise make the first commit itself. You own the git workflow: git init and commit this lesson yourself.
--skip-testsNo .spec.ts next to every file, same as learn-angular. angular.json keeps skipTests for ng generate.

2. Zoneless from day one

In learn-angular (lessons 10 and 14), zone.js re-checked the whole app after every event, timer and animation frame. That's why GSAP and Three.js loops had to run inside runOutsideAngular.

  • Here there is no zone.js in package.json or angular.json polyfills, and no provideZoneChangeDetection() in app.config.ts.
  • A template updates only when a signal it reads changes, or a template event handler runs. ≈ React: a re-render only after setState.
  • A Three.js setAnimationLoop or a GSAP ticker can run at 60 fps and Angular won't notice. That's exactly what we want: per-frame work stays in Three.js and GSAP, and only meaningful state (selected country, year) goes into signals.
  • The trap: a plain class field changed from a timer or a fetch callback won't show up on screen. Everything the template reads should be a signal.

4. Routes

''          → Explorer (eager, in the main bundle)
'lessons'   → loadChildren → lessons.routes.ts
  ''        → Roadmap        (lazy chunk)
  'setup'   → LessonSetup    (lazy chunk)
  • The product page is eager: it's the first thing a visitor sees. Lessons are a lazy subtree, so the product doesn't download any lesson code.
  • lessonRoutes is its own exported array on purpose. Lesson 01 mounts the same array a second time, in a named outlet (/(lesson:lessons/setup)), to show any lesson in a floating window over the live product.
  • Route title sets document.title. ≈ Next.js metadata.title.

5. Styles

  • styles.scss holds the tokens (--bg, --accent, …) and the shared .nsc-lesson typography. Dark only: the globe needs a dark background.
  • Component styles are scoped by Angular (≈ CSS Modules). Class names follow the workspace style guide: nsc- on the component root only, plain nested names, is- for state.
  • The explorer shows a CSS sphere where the globe will go. The layout already has its final shape: header, then a stage filling the rest of the viewport.
